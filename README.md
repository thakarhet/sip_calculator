# Growwise — SIP & Mutual Fund Calculator

A full-stack investment planning starter with a responsive React calculator, Express API, MongoDB persistence, JWT authentication, and security middleware. The projection is educational and does not recommend or guarantee mutual fund returns.

## Features

- SIP projections with monthly or quarterly contributions and optional annual step-up.
- Lump sum compound growth projection.
- Interactive sliders and estimated investment/growth breakdown.
- Downloadable text summaries generated by the API only after authentication.
- Register and sign in with bcrypt-hashed passwords and signed JWTs.
- Save, list, and delete plans through authenticated API endpoints. Plans are scoped to their owner.
- API protections: Helmet headers, strict configurable CORS, request body size limit, input validation, auth rate limiting, JWT algorithm pinning, and generic login errors.

## Requirements

- Node.js 20 or newer and npm.
- MongoDB Community Server or a MongoDB Atlas connection string.

## Run locally

1. Start MongoDB locally, or create a database in MongoDB Atlas.
2. Copy `server/.env.example` to `server/.env` and set `MONGODB_URI` and a unique `JWT_SECRET` with at least 32 characters. Keep this file private.
3. From this directory, install dependencies:

   ```sh
   npm install
   npm --prefix server install
   npm --prefix client install
   ```

4. Run the API and Vite development server together:

   ```sh
   npm run dev
   ```

5. Open <http://localhost:5173>. The API listens on <http://localhost:5001>; Vite proxies `/api` requests to it.

For production, set `CLIENT_ORIGIN` to the deployed frontend origin(s), use a strong secret from a secret manager, serve the frontend over HTTPS, and run `npm run build` before hosting `client/dist`. The API needs the same environment variables and a reachable MongoDB database.

## Environment

| Variable | Purpose | Default |
| --- | --- | --- |
| `NODE_ENV` | Runtime mode | `development` |
| `PORT` | API port | `5001` |
| `MONGODB_URI` | MongoDB connection string | Required |
| `JWT_SECRET` | JWT signing key (32+ characters) | Required |
| `JWT_EXPIRES_IN` | JWT lifetime accepted by `jsonwebtoken` | `1d` |
| `CLIENT_ORIGIN` | Comma-separated allowed browser origins | `http://localhost:5173` |
| `BCRYPT_ROUNDS` | Password hashing cost | `12` |

## API

- `GET /api/health` — liveness check.
- `POST /api/auth/register` — `{ "name", "email", "password" }`.
- `POST /api/auth/login` — `{ "email", "password" }`.
- `GET /api/auth/me` — current user; requires `Authorization: Bearer <token>`.
- `GET /api/plans` — list the signed-in user's saved plans.
- `POST /api/plans` — save a validated plan; requires bearer token.
- `POST /api/plans/export` — generate and download a projection summary; requires bearer token.
- `DELETE /api/plans/:id` — remove an owned plan; requires bearer token.

The web demo keeps its short-lived bearer token in `sessionStorage`, which clears when the browser tab session ends. For a production deployment exposed to untrusted scripts, consider an architecture using secure, `HttpOnly`, `SameSite` cookies with CSRF protection and a refresh/revocation strategy.

## Projection assumptions

SIP contributions are applied at the beginning of each period and compounded at an effective periodic rate derived from the annual rate. The annual step-up is applied at each year boundary. Lump sum uses annual compounding. These are simplified illustrations; real fund NAV movements, fees, taxes, timing, and return sequences differ.
